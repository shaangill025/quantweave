Claim one bounded task, write/refresh its execution plan, add failing tests before substantive implementation, run the real bound checks, review diff and record evidence. Load deep specs only for relevant modules; keep a compact handoff with decisions, changed files, commands actually run, outcomes and next ready task. Reviewers challenge code, numerical assumptions, permissions, concurrency and invalidation, not only formatting. Do not lower tests, risk thresholds, verification rules or release gates to make a task pass. Generated code experiments are untrusted and may not control host/runtime/assessor/keys.
