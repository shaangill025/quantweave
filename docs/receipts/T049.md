- **Evaluation.** `evaluate` re-runs the gate (a refused candidate never reaches the stager) and requires the stager's written-tree digest to equal base + patch; that digest covers the candidate tree only, not the interpreter or the rootfs. It runs the profile's protected argv and limits via `sandbox.execute` with run id `code-<digest[:24]>-a<attempt>`. Pass means exited, exit 0, a bound run id, exactly `expected_passed` passed, nothing failed/error/skipped/xfailed/xpassed/deselected and no truncation. That summary comes from a process the candidate's code shares, so a pass is unverified (`in_process_test_summary`). A hand-built `Evaluation` is rejected only when it is internally inconsistent; a self-consistent forgery is not detectable, so persistence must store only `evaluate`'s output. **Hand-off.** `check_protocol` requires the code target, installation scope (R039), the profile base as `baseline_hash` and the profile digest as `mutation_space_hash`; `package` re-checks protocol, candidate and evaluation bindings. `route_for_review` gives a state, the required approval classes, no grant field, `automatic` False, `blocked_by=("sandbox_unqualified",)` and the bundle's `limitations`.
