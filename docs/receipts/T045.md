### Rules
- **Closed knob set (verification: no widening).** `ADAPTABLE` has exactly eight keys: `coalesce_minutes.<c>` (0 to 1440; monitoring_alert at most 240) and `mute_external.<c>` (true or false) for the three non-safety categories (proposal, monitoring_alert, job_outcome), plus `explanation_verbosity` (brief, standard, detailed) and `explanation_format` (prose, bullets). Any other payload key is refused, never ignored:
  - `widens_authority` when the key names policy, risk, limits, sizing, position, mode, approvals, leverage, margin, orders, broker, strategy, instruments, options, drawdown, stops, allocation, budget, consent, sharing, export, scope, tenant, assessor, scorecard, threshold, holdout, safety, exposure or account;
  - `not_adaptable` for anything else.
  The safety category (`risk_pause`) cannot be muted or coalesced (`safety_category`). Values are parsed strictly and canonically: strings only, no leading zeros, at most four digits. Mutes apply to external channels only (`apply`); the in-app record is not touched.
- **Producer (R031, R084).** `propose` reads only through T043 `select(tenant, experiment, personal_adaptation, development)`, so every read is logged as a `Use`, and only the tenant's own records. Rules v0:
  - two or more `irrelevant` reports on notifications add 60 minutes of monitoring-alert coalescing, unless any `missed_risk` report exists;
  - more `unclear` than `clear` reports on other subjects raise verbosity one step.
  `candidate` turns the result into a T044 `Candidate` whose artifact hash is the configuration hash and whose evidence uses are the logged `Use`. T044 `register_candidate(c, evidence)` checks that log.
- **Private protocol (R031, R039).** `check_protocol` requires target `personal_adaptation`, scope `tenant` and evidence purpose `personal_adaptation`; otherwise `not_private`. Installation-scope or shared-improvement protocols are refused, so a private adaptation cannot become a shared change. The scorecard must also hold `missed_safety_alerts` and `payload_invalid` as hard `at_most 0`; otherwise `safety_control_missing`.
- **Scorecard.**
  - Hard (`at_most 0`): the T044 §11 controls `risk_broadened` and `private_export`, plus `missed_safety_alerts` and `payload_invalid`.
  - Goals, measured against the frozen baseline:
    - `improved` ≥ 1, meaning `redundant_alerts_removed` ≥ 1 or `explanation_mismatch_change` ≤ −1;
    - `redundant_alerts_removed` ≥ 0;
    - `relevant_alerts_lost` ≤ 0;
    - `explanation_mismatch_change` ≤ 0.
- **Independent measurement.** `measure` is run by the assessor:
  - It checks that the baseline it is given matches the protocol's `baseline_hash`, and that the candidate belongs to the protocol's experiment and target (`candidate_experiment`).
  - It refuses a fixture with no relevant alert in a category the candidate mutes or coalesces differently from the baseline (`fixture_category_uncovered`), since that change would go unmeasured.
  - It refuses a fixture with no non-safety must-deliver case (`fixture_no_safety_case`). Without one, `missed_safety_alerts` could not detect a suppressed alert, because safety alerts are always delivered.
  - It re-reads the raw candidate payload. A key outside `ADAPTABLE` scores `risk_broadened`. An unparsable, non-canonical or out-of-range value scores `payload_invalid` instead of raising; the remaining valid keys are replayed.
  - It counts any evidence use that is not this tenant's personal, recipient-free and consent-free use as `private_export`.
  - It replays the fixture's alerts with the `notifications.Center` rule: safety is always delivered; a repeat for the same (category, object) inside the window coalesces and does not move the window; the window end is exclusive.
  The metrics reach a verdict only as the assessor's T032 promotion trial, read by T044 `assess`. The producer's numbers are never used.
- **Reversible private state (R031, R039).** `PrivateState` is one tenant's version list.
  - `adopt` runs every check before changing anything: the registry is this tenant's; the protocol is private; the candidate's latest verdict is `accept_for_review` (`not_accepted`); the protocol's baseline hash is the active configuration (`stale_baseline`); the candidate's artifact hash is the hash of its payload's configuration (`artifact_mismatch`); each approval class the protocol froze is present for this candidate (`approvals_missing`; for personal adaptation that is operator install and user adoption, from T044 `MIN_APPROVALS`); no approver is the producer or assessor actor (`approver_not_human`); every approval falls between the verdict and the adoption (`approval_before_verdict`); install comes no later than user adoption (`install_after_adoption`); each candidate is adopted once (`already_adopted`).
  - `versions` is a read-only tuple.
  - `rollback(n)` restores any retained version as a new version `rollback:n`; history is never edited.
  - `export` returns only this tenant's history.
  - `erase` drops every stored configuration and hash, keeps version numbers and sources, and makes the default active; later rollback to an erased version is `erased`.
