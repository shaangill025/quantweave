The client only adds a "Past expiry, not actionable" tag and never upgrades a state.

## Negative/adverse cases
- Client fails closed on: a problem body (keeps the code and correlation id), a 502 with no problem body, a network rejection, a non-JSON 200, a float amount `0.5`, the exponent string `"5e-1"`, a timestamp without an offset, and an unknown freshness enum. A missing endpoint (404 `not_found`) shows "Unavailable (not_found)" and "Not connected". The Overview then does not claim that "nothing needs attention".
- A snapshot whose `account_id` names another account is refused (`snapshot_account_mismatch`) and its figures are not shown.
- An empty `available_cash` shows `Unavailable (no_cash_observation)` and the cash table contains no `0`. 2^53+1 (`9007199254740993.01 CAD`) displays exactly.
- Limit draft rejections: `1e3`, `1,000`, `-0.5`, `0.000`, `" 1"`, 13 whole digits for a ratio, 13 decimals for an amount, a missing currency, an unknown metric, and an empty denominator. `0.30000000000000000` is kept as typed.
- Mutation controls (run, then reverted; `cmp` confirmed the restore), each failing at least one test: past-expiry detection off; empty cash rendered as `0`; no focus move after navigation; hypothetical accounts mixed into the real table; negative limits allowed; snapshot account check removed.

## Review fixes (round 1)
The cross-model review asked for changes. Each new or extended test was run against the pre-fix code first, and 9 failed: the two S1 tests, the S2 test, the N7 assertion, the N2 assertion and four N1 cases. All pass after the fix.
- **S1.** In-page links collided with the hash router. The router now ignores hashes that do not start with `#/`. The skip link and the error-summary links focus their target with `focusTarget`, without changing the hash, so the view and the draft are kept. Tests: the skip link focuses main; a stray `#main` hashchange keeps Decisions; a summary link focuses `limit-metric` and keeps the error summary.
- **S2.** There is no all-clear unless every source is complete (`next_cursor` null and coverage not partial). `Completeness` shows "[Partial list] reasons" and "more records exist" on the Overview, Accounts, Policies and Proposals. Test: three complete empty sources give the all-clear; a partial-coverage source plus a next-cursor source do not.
- **N1.** The account `id` must match the contract id pattern, so `""`, `.`, `..` and `a/b` are refused before a path is built.
- **N2.** Any edit clears "Draft is well formed". Switching to ratio drops the currency problem, so the summary does not link to a field that is not rendered.
- **N4.** Legs and positions are keyed by index and instrument.
- **N7.** When a source fails, the Overview adds: "Some records could not be loaded, so this list may be incomplete."
- Not changed (size limit):
  - N3: re-opening the already open snapshot does not move focus.
  - N5: decimals longer than the client's 26.18 digits fail closed as `invalid_response`.
  - N6: a proposal in an unknown state is not listed under Needs attention.
  - N8: the draft accepts a ratio above 1; the server decides the range.
- Rerun after the fixes: see the "Actual checks" table; `pnpm test` now passes 162 tests.
