### Interpretations (for review)
- **Publication time.** When the submissions payload gives the accession, publication time is its `acceptanceDateTime`. Otherwise it is a conservative bound: filed date D + 1 day at 05:00Z, which is at or after the end of D in New York under EST or EDT. That bound needs no timezone database. Acceptance after our receipt is refused as impossible. Acceptance outside [D-4 days 00:00Z, D+1 05:00Z] is refused as `acceptance_filed_mismatch` (review S3, then widened at review request). The lower bound accommodates next-business-day filing dates after weekends and holidays without a qualified calendar. For example, a filing accepted after 17:30 ET on a Friday before a Monday holiday has filed date Tuesday, about 3.3 days later. Only an early acceptance can leak, so a mis-stated acceptance time can make a fact knowable at most about 4 days early. A qualified EDGAR business-day calendar would tighten this later.
- **Two knowledge bases.** `PUBLICATION` (what was public) is the backtest available-data rule (R098). `RECEIPT` (what this system had, max(published, received)) is the live view.
- **Versions.** A version is (fact key, accession), where the key is CIK, taxonomy, concept, unit and period. A later accession for the same key is a restatement and never overwrites. Re-ingesting a version is idempotent and keeps the first receipt. The same version with a different value is refused (`fact_conflict`). Versions tied at the latest knowledge time with different values are reported as `conflicted` and never chosen.
- **Units.** An allowed currency (default `USD`, `CAD`), `shares`, `<currency>/shares` and `pure` are accepted. Any other unit series is refused and listed, while the other series still load. Malformed structure refuses the whole payload.
- **Value bounds.** Values are limited to 26 integer digits and 12 decimals, matching the money scale. Larger values are refused, never rounded. Scale is counted from the digit tuple with trailing zeros stripped, with no context rounding (review S1). Zero forms such as `0E-30` and `-0` are accepted as zero (N3). A JSON integer past the 4300-digit conversion cap maps to the typed `json` error (S2).
- **Ingestion uses.** Ingestion requires the `retention` and `derived_data` uses. Display and model use stay with their consumers.

## Negative cases (SYNTHETIC)
- **Rights.** Ingestion is denied when `retention` or `derived_data` is missing from the entitlement, and when the registry has no such feed. Each case is checked for both entry points.
- **Values.** 13-decimal, 61-significant-digit, 1E+26 and 4401-digit integer values are refused, as are NaN, Infinity, string, boolean and null values, duplicate JSON keys, start after end, and pre-parsed dicts.
- **Units.** `usd`, `EUR`, `shares/USD`, `USD/USD`, `Vote`, `USD-per-share`, empty and trailing-space units are refused, not coerced.
- **Filings.** Companyfacts whose form or filed date contradicts submissions is refused. Acceptance after receipt is refused. For acceptance against filed date 2026-02-01: 2020-02-01 and 2026-01-27T23:59:59Z (D-4d minus 1 s) are refused; 2026-01-28T00:00Z is accepted; Friday 2026-02-13T22:45Z is accepted for filed date Tuesday 2026-02-17 (after Presidents' Day); 2026-02-02T05:00Z is accepted; 2026-02-02T05:00:01Z and 2026-02-05 are refused.
- **Versions and queries.** One accession carrying two values is refused, and tied versions are reported as conflicted. A naive `as_of` time is rejected.
- **Exactness.** 2**53+1 stays exact, 0.1 + 0.2 = 0.3, and 1.5E+3 = 1500.
- **Restatement sequence (hand-written).** Before the first publication the fact is absent. It is visible exactly at publication. Values are 1000 → 990 → 985 over time, with history kept. Under the receipt basis the value is 1000 where the publication basis shows 990.
- **Property.** No as-of result has a knowledge time after the query time. Each result is the latest known version. Visible keys and chosen knowledge times are monotone in the query time. Knowledge times come from a small range, so tied versions are frequent, and a key is conflicted exactly when its latest-known versions disagree (N2).
- **Mutation controls.** Worker self-report, run on the working file and reverted. 11/11 mutants were killed: `>` changed to `>=` in as_of; the bound hour changed to 4; the scale limit changed to 13; tie conflict detection off (now also caught by the property alone); any `<cur>/<x>` accepted as per-share; trailing-zero scale count off; acceptance window widened at either end (2 mutants); widened lower bound moved to 4 days minus 1 s and to 5 days (2 mutants).
