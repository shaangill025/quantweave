### Rules
- **Closed knob set.** `Policy` has exactly seven payload keys: `material_kinds`, `conflict_tolerance`, `min_alternatives`, `max_revisions` (0 to 1), `review_max_cost_usd` (above 0, at most USD0.10), `pass_output_tokens` (64 to 2000) and `pass_timeout_seconds` (1 to 30). Values are parsed strictly and canonically. A distinct model family is always required and is not a knob. Any other key is refused and named: `answer_key` (answer, key, label, expect, case, holdout, oracle, truth, control), `widens_authority` (risk, policy, threshold, scorecard, approval, assessor, family, isolation, budget, order, broker, limit, gate, code, prompt, instruction, route, model, verification, evidence, scope, tenant), otherwise `not_adaptable`. The evaluator's own `Config` refuses a floor-dropping kind set or an out-of-bound tolerance, so the floor holds even outside this module.
- **Fixed evaluation control.** A `Case` holds the thesis, record, mandate, evidence store, proposer route, review time, recorded replies and an optional revision. `freeze` returns a `Manifest`: the ordered (case id, case hash) pairs plus a salted commitment to the labels, never the labels. The case hash covers the thesis, record, mandate, proposer, replies, revision and the evidence exactly as `researcher.snapshot` re-freezes it at the review time. The manifest hash is the T032 plan's `protocol_hash`; T044 `plan_digest` covers it, so the protocol freezes the control. `freeze` refuses duplicate case or mandate ids, a key that does not cover exactly the cases (`key_cases`), and a control without both labels (`unbalanced`).
- **Tamper rejection (R092).** `measure` refuses before any key read: a plan or manifest the protocol did not freeze (`control_not_frozen`), and any of `case_modified`, `case_added`, `case_removed`, `case_duplicated`, `case_reordered`, `key_modified` (`control_tampered`, naming each).
- **Answer key access (R084).** `AnswerKey.read` returns the labels only for a granted promotion access with role assessor, sequence 1 (the plan's first holdout read), the protocol's plan and assessor actor, and this candidate's trial key; each access is read once (`key_reused`). The producer has no read path; its promotion request is refused by the ledger (`assessor_only`). Case ids or label words in a candidate payload count as `answer_key_mutations`.
- **Measurement.** `replay` runs one case through the real T039 `evaluate` with the policy's config, a deterministic clock that moves only by recorded latency, a replay adapter (a reply past the pass deadline times out), and a fresh gateway budget book. When the review asks for a revision and the case holds one, the revision is evaluated with `prior`. A case counts as approved only when the final outcome is `approve_for_final_checks`. `measure` scores the baseline and the candidate on every case:
  - hard (`at_most 0`): `answer_key_mutations`, `unverified_claims_accepted` (an approval with a material ground or a failed re-check; T044), `false_approval_increase` (candidate minus baseline false approvals), `policy_widened`, `payload_invalid`;
  - goals, bounds frozen in the scorecard: `improved` ≥ 1 (fewer false approvals or fewer over-rejections), `over_rejection_increase`, `latency_increase_seconds`, `cost_increase_usd` (each at most its bound, default 0);
  - reported: counts and rates (4 decimal places) for both policies, latency (sum of run durations), cost (book reserved plus spent, so an unknown outcome is charged at its hold).
  
  The hard rule interprets §11 "reduce harmful approvals": false approvals may never increase versus the baseline. The metrics reach a verdict only as the assessor's T032 promotion trial read by T044 `assess`.
- **Scope and authority (R030, R039, R099).** `check_protocol` requires target evaluator and installation scope (`not_installation`), and a scorecard holding the hard controls (`control_missing`) and the four goals within their caps (`goal_missing`; round 1). Approvals stay those T044 freezes for the evaluator (maintainer release and operator install). The module has no approve, install, adopt, promote, sign or grant function (tested).

## Negative and adverse cases (SYNTHETIC; not release proof)
Control: `ok`, `round` (a later filing at 100.3 against 100), `soft` (an interpretation contested) and `revise` (a contested fact, then a resolved revision) should approve. `restated` (90), `near` (99.2, a 0.8 % restatement) and `assume` (an unsupported assumption) should block. Every pass is 100 input and 50 output tokens, so USD0.00105; blind replies take 2 s and compare replies 3 s.
- **Baseline** (T039 defaults): it approves `assume` (1 false approval, rate 0.3333) and over-rejects `round` (1, rate 0.25). That is 8 evaluations, 40 s and USD0.0168.
- **Helpful** (assumption material, tolerance 0.005): 0 false approvals and 0 over-rejections, with the same latency and cost. Verdict `accept_for_review`, limitation `synthetic_only`.
- **Lax** (tolerance 0.01) approves `near`: 2 false approvals, rejected `hard:false_approval_increase` even though `improved` is 1.
- **Strict** (interpretation material) over-rejects `soft`; **no revision** rejects `revise`, 5 s and USD0.0021 cheaper. Both are rejected `goal:improved`, `goal:over_rejection_increase`.
- Against a no-revision baseline, allowing the revision is rejected `goal:latency_increase_seconds`, `goal:cost_increase_usd` under zero bounds, and accepted with bounds of 5 s and USD0.0021.
- **Payload attacks:** `answer_labels`, a case id in a value, a label word in a value → `answer_key_mutations`, and the verdict is rejected `hard:answer_key_mutations`; `risk_override` → `policy_widened`; `pass_timeout_seconds` 99 or `min_alternatives` "two" → `payload_invalid`.
- **Control tampering:** each of a modified, added, removed or reordered case and a flipped label is refused, and the key read count stays 0. A re-frozen v2 manifest is `control_not_frozen`.
- **Key access:** a producer-role request, another assessor actor, another candidate's access and a second read are all refused.
- **Pass timeout:** a 2 s timeout cuts the 3 s compare reply. The result is a `model_failed` abstention with the reservation held.
