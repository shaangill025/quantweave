### Review fixes (after `b31a88f`)
- `adjust_option` no longer double-applies. Contract versions record `applied_actions` as (event_id, version), and re-applying an absorbed event id is rejected, whether it is a duplicate or a corrected version. Before the fix, the same 2:1 split applied twice gave 400. `replay_option(base, log, known_as_of)` rebuilds terms from base terms (no applied actions) with the current version of each logged event known at that time, in (effective, event_id) order; this is how a correction replaces the version it supersedes.
- `CorporateActionLog`: a correction may change the effective date and terms, and both versions stay in `history`. It may not change `instrument_id`, which is rejected. Reason: effects already derived for the first instrument (adjusted contracts, later ledger postings) would lose their cause silently, so a wrong instrument is corrected by a new event id.
- `PositiveRatio`: terms bounded by 10**18 after reduction, decimal strings limited to 18 integer and 18 fractional digits, and `ValueError`/`OverflowError` from `from_decimal` wrapped as `CorporateActionError`. The int-to-string digit limit could otherwise be hit when printing a huge ratio.
- `CalendarVersion`: `require_date` on holiday, early-close and ad-hoc closure dates.
- **Recorded limitation:** ordinary cash dividends never adjust option terms, and `special` is supplied by the source. A mislabelled extraordinary dividend therefore leaves a verified contract unchanged. Quarantine of unknown or uncertain actions belongs to T012. The limitation is also stated in the module docstring.
- Post-merger `underlying_id`: `adjust_option` keeps the original underlying id and changes only deliverables. How the underlying of a converted contract is represented belongs to T034.

### Assumption to confirm
- Spec 04 does not state a dividend date ordering. Enforced where supplied: announced ≤ ex and ≤ record, record ≤ pay, and for ordinary dividends ex ≤ record and ex ≤ pay (T+1: ex == record; T+2: ex one business day earlier). `special=True` skips the ex-date ordering to allow due-bill distributions whose ex-date follows the pay date. Which dividends are "special" for option adjustment is supplied by the source, not derived.
