## Negative/adverse cases
- Wire rejects `-0`, `-0.000`, 27 integer digits, 13 decimals (even zeros), `01`, `1e5`, `+1`, `1.`, `.5`, whitespace, `"1\n"`, Arabic-Indic digits, `NaN`/`Infinity`, and JSON numbers. Decimal input rejects NaN, sNaN, ±Inf, -0, excess scale and range. Floats are rejected for every class (property test). Mixed float/int/Decimal/other-class comparisons and arithmetic raise `TypeError`. Mismatched currencies raise.
- Timestamps: missing offset, `-00:00`, 2026-02-30, 2026-02-29, month 13, hour 24, second 60, 7 fractional digits, `z`, a space separator, `+25:99`, a trailing newline, non-ASCII digits, year 0 and year 1 at +01:00 are all rejected. Naive datetimes are rejected.
- C-05 schema layer: with rfc3339-validator, `format: date-time` rejects `2026-10-08T10:00:00` (AT080 negative half, at schema level). Finding for T010/T011: jsonschema applies `pattern` with `re.search`, so `$` accepts a trailing `\n`, and the review's `\d` matches non-ASCII digits. Pattern plus format still accept `…Z\n` and `0001-01-01T00:00:00+01:00`. A test pins this, and only the semantic parser rejects them. The domain regexes use `[0-9]` and `fullmatch`.
- Guards: injected SYNTHETIC samples make both checks fire. Boundary: fastapi, openai, `importlib.import_module('alpaca.trading')`, psycopg in domain src, starlette in tests, and a package with no rule. No-float: `b: float`, `0.1`, `1e3`, `float(s)`, `'list[float]'`, `cast(float, …)`, `Decimal.from_float`. The `Decimal == float` sample type-checks under mypy 2.4.0 but fails `check_no_float.py`. ruff fires TID251/DTZ003/DTZ005 on `datetime.utcnow()` and naive `datetime.now()` in a scratch sample.
- Mutation checks on the final code (each reverted): accepting float, dropping the -0, scale, range, positivity or currency checks, COST→CEILING, DISPLAY→HALF_UP, `fullmatch`→`match` for decimals, exact-type→`isinstance` in comparisons, dropping the `-00:00` lookahead, and skipping UTC conversion each failed 1–7 tests. Two mutants survived because the code has redundant defences: removing `re.ASCII` (the patterns already use `[0-9]`) and `fullmatch`→`match` for timestamps (`fromisoformat` rejects the newline).
- Process: the tests were written before the implementation, but their first run came after the code existed, so no red run was recorded.
