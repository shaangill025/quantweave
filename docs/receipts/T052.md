### Rules
- **Classification (R031, R039).** Every learned or derived item is a node `<kind>/<scope>/<id>` (`/` is outside `ID_PATTERN`): T043 record and consent, T044 candidate (with its content hash) and verdict, T045 adaptation version, T051 release (bound by protocol and candidate hash, else `release_unbound`). Each carries origin (`private_tenant`, `shared`, `synthetic`), basis (`own_data`, `consent`, `none`), purpose and inputs (the records and consents of the candidate's logged `Use`s, parent candidate, adopted candidate or rolled-back version). Withheld holdout and tombstoned records are classified private.
- **Invalidation (R052, R087; spec §12).** A deleted record (`record_deleted:<id>`) or revoked consent (`consent_revoked:<id>`) invalidates every downstream node: not reproducible, all root causes listed. A missing input fails closed (`lineage_missing`); erased versions read `erased`. The walk is iterative (deep chains are fine; a cycle raises `lineage_cycle`). Actions: active personal adaptation `rebuild_or_rollback`; other derived items `blocked`; shared release `retire_or_rebuild`.
  - **Release rule (owner review):** spec §12 says a derivative that cannot be selectively unlearned is retired or rebuilt, or kept only under a lawful disclosed exception. The flag triggers that maintainer decision; nothing is uninstalled and no tenant is moved (T051).
  - `learned_state.adopt`/`rollback` refuse invalidated nodes (`invalidated`) reading every deletion and revocation recorded, whatever time the act asserts. `adopt` also refuses a lineage whose candidate hash differs from the registry's (`lineage_registry`).
- **Export (R051, R096).** Five canonical-JSON files (records, consents, adaptation, candidates, lineage) and a manifest valid against `export_manifest.schema.json`, content-addressed by SHA-256.
  - Statuses count every recorded deletion and revocation, whatever `at` says. A lineage not built from this evidence store, or not matching the state's versions and erased flags or the registries' candidates, is refused (`lineage_stale`).
  - Every adaptation row is `"status": "inactive"`. Final-holdout case content and deleted records are omitted. A candidate payload is exported only for a personal-adaptation configuration when the tenant has erased nothing (else `erased` / `not_configuration:<id>` omissions). Verdict reasons and limitations are dropped for non-configuration targets.
  - Declared omissions: `approval` (`authority_not_portable`), `shared_release` (`installation_scope`). `contains_credentials`/`contains_executable_code` are `false`.
  - The scan admits only allowlisted keys (one allowlist for all five files) and refuses credential/authority/activation fragments (`forbidden_field`), other tenant ids or lineage nodes (`foreign_tenant`), `status` other than `inactive` (`activation`) and nesting deeper than 16 (`malformed`).
  - Optional `principal_id` keeps only that principal's feedback and grants (`other_principal:<n>` omission). The pilot tenant is single-principal, so the owner's export is the tenant's.
- **Import (R051, R087).** Every failure is a typed `LearnedStateError`. Order: manifest fields; credentials/executable flags; format; `scope_mismatch`; manifest shape (ids, instant, hex hash, entry keys and types, omission vocabulary: `manifest`); `manifest_hash`; exactly the five paths (`path`); size (`oversized`); `file_hash`; `classification`; strict UTF-8 JSON with no float, NaN, BOM or duplicate key (`float`, `duplicate_key`, `malformed` for huge ints, deep nesting, bad JSON); the scan; unique positive version numbers with a hash (`adaptation_version`); T045 strict re-parse and hash (`adaptation`, `adaptation_hash`). `Imported` is inert: it becomes active only as a new candidate, assessed and adopted (tested: `not_accepted` without a verdict).
