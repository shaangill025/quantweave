Rules (the docstring states them):
1. **Gap 1, broker mutation: stricter option chosen.** Every mutating amended operation is refused, whatever its name, until an owner-approved mutation allowlist exists. So is any other method that is not GET. Contract 0.7.0 adds only GET. Spec rule 1 (`ALLOWED_MUTATIONS`) is unchanged.
2. **Shape first (`check_shapes`).**
   - Every structural amendment key must be one a rule reviews. This covers the top level, `schemas.<n>`, `requests.<n>`, `page`, path items (methods plus `summary`, `description`, `parameters`), operations (`operationId`, `summary`, `description`, `security`, `parameters`, `requestBody`, `responses`), parameters (`name`, `in`, `required`, `schema`, `description`, or `$ref` alone), responses (`description`, `headers`, `content`), header objects (`schema`, `description`, `required`) and media-type objects (`schema`). So `x-*`, `tags`, `links`, `callbacks` and `examples` are refused. JSON Schema keywords inside schemas are not gated; rules 3, 5 and 7 read them. A parameter's `in` must be `query`, `header`, `path` or `cookie`. The name of a parameter refused for its `in` is still scanned (rule 7 does not run on a refused shape).
   - Each value must have the type the rules read: objects, lists, lists of strings, lists of objects, a `responses` object, response objects, `headers` and `content` maps of objects, a `security` list and a `parameters` list of objects.
   - A malformed amendment is reported and not applied, so no later rule can raise on it.
   - `project_contract` failures (KeyError, ValueError, TypeError, AttributeError, IndexError) are reported as refusals.
   - Response keys are only the spec's own codes: `200`, `201`, `202` and `default` (72 spec operations use only these, and errors go through a `default` Problem). So `2XX`, `2xx`, `204`, 1xx, 3xx and 4xx are refused. A 2xx content map must be exactly `application/json`, and `default` must be exactly `application/problem+json`. `servers` is refused on a path item and on an operation.
   - Any exception a rule raises on an amended document is reported as `checker crashed on malformed amendment: <type>` (exit 1), in the CLI and in the self-test. A `type` list holding non-strings (for example `[[]]`) no longer raises TypeError in the decimal rule.
3. **Gap 2, tenant parameter.** Operation-level and path-level parameters are both checked. `$ref`s are resolved through `#/components/parameters/` (8 hops). A `$ref` that does not resolve is reported.
4. **Gap 4, 2xx body and security.**
   - Every 2xx is checked. Each must name a known component.
   - The body is refused if it reaches Problem through `$ref`, allOf/oneOf/anyOf or if/then/else/not at any depth (component and schema-file refs are followed). A cycle or a ref that does not resolve counts as Problem.
   - Each 2xx must carry no-store.
