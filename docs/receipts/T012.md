## PR A — postings and event constructors

### Changes
- `packages/domain/src/qw_domain/postings.py` (new)
  - `SourceObservation`: account, `SourceRef`, `observed_at`, `effective_at`, a read-only string payload and a SHA-256 fingerprint over account, source, record, effective time and payload. Receipt time is excluded.
  - `MoneyPosting` (`BookAccount`, `Money`, optional instrument sub-ledger) and `UnitPosting` (`UnitAccount`, `InstrumentId`, `Quantity`) on one `JournalEvent` (C-12).
    - Each set is empty or has at least 2 lines, and at least one set is non-empty. Zero lines are rejected.
    - Money balances per currency (F-01). Units balance per instrument against `unit_clearing` or `corporate_action_clearing` (F-02).
    - Only `Money` and `Quantity` are accepted, so scale violations are rejected, never rounded.
  - `event_id` fingerprints source identity plus economic content. The idempotency key is tagged: `("record", account, source, record)` or `("reversal", account, original_id)`. No source id can forge a reversal key.
  - Constructors (spec §4 "Supported economic events"): `deposit`, `withdrawal`, `fee`, `interest`, `dividend` (cash payment), `buy`, `sell`, and `split` (forward and reverse).
    - Cost convention, spec §5 "Cost and P&L reference convention" and spec §4 "Monetary and unit ledgers" (F-03): acquisition fees capitalise into cost; disposition fees reduce proceeds.
    - A partial sale takes proportional cost. Spec §5 names no lot-selection method, so this is average cost, `economic_average_cost/1`. The remaining cost is rounded up at scale 12 using exact `Fraction` arithmetic, and allocated = cost − remaining.
    - The raw fee is kept on the event.
  - `Holding` carries account and instrument. `sell` and `split` reject a holding for another account or instrument (`holding_mismatch`). `sell` also rejects `short_sale_unsupported` and `cost_unknown`. `split` rejects `split_not_long` and `split_fraction` (quarantine, e.g. 100 × 1:3).
  - **Limitation:** the constructors trust the `Holding` snapshot they are given; PR B's `Journal.sell`/`Journal.split` derive it from the journal.
- `packages/domain/tests/test_postings.py` (new, 26 tests, SYNTHETIC)
  - NUM01 postings and NUM02 split postings, with values read from `numerical_oracles.json`.
  - Rounding: cost 100 over 3 units, sold 1, 1, 1, checked against an exact `Fraction` ceil oracle. Remaining is 66.666666666667, then 33.333333333334, then exactly 0, and allocated + remaining = cost at each step.
  - 18 rejection cases.
  - Type and scale rejections.
  - Cash-only events and the reverse split.
  - Fingerprints and the forged reversal key.
  - Properties: every generated event, and any list of them, balances per commodity; a split preserves qty × price exactly with no money postings.
