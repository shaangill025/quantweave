## Changes
- `packages/adapters/src/qw_adapters/sql/0009_policy.sql` (new)
  - `app.policy_version (tenant_id, policy_id uuid, version, content_hash, content jsonb, label SYNTHETIC|LIVE, created_at default now(), created_by)` with composite FKs to tenant and app_user.
  - `app.policy_adoption`: the receipt columns (principal, session, step_up_at, step_up_receipt_id, signed_at default now(), policy_hash, label, limits, acknowledged, exclusions, acknowledgement text, receipt_hash). The primary key `(tenant_id, policy_id, version)` admits one adoption per version. A composite FK binds `(version, policy_hash, label)` to the version row.
  - Both tables: FORCE RLS on `app.current_tenant_id()`. Statement triggers refuse UPDATE, DELETE and TRUNCATE for every role (`app.journal_append_only`). `qw_app` gets SELECT plus column INSERT, never `created_at` or `signed_at`. `qw_worker` gets nothing yet.
  - A row trigger takes the policy's advisory lock and refuses:
    - a version that is not the latest + 1;
    - an adoption of a non-latest version;
    - an adoption whose session is not the principal's own live session;
    - an adoption whose `step_up_at` differs from the session's current value or is more than 1 hour old;
    - a `step_up_receipt_id` other than `<session id>.<step_up_at epoch µs>`.
- `packages/adapters/src/qw_adapters/policy_store.py` (new)
  - `propose` appends a version only when the content hash changes.
  - `adopt` does all of the following in one transaction, under the advisory lock:
    - loads the history (`not_found` for an unknown or other-tenant id);
    - checks the principal's live session (`FOR SHARE`, so a step-up refresh or revoke waits for the commit) and its step-up against the caller's window (`step_up_required`; a trigger refusal maps to it too). The 1-hour cap is T010's `step_up_window` bound, not a spec value. This ties the receipt to the session's `step_up_at`; per the T010 API-trust item, qw_app can write that column, so a compromised qw_app can forge a step-up;
    - checks the content hash of the latest version (`stale`);
    - runs the domain `adopt` (`not_latest`, `already_adopted`, conflicts, limits);
    - inserts the receipt. `signed_at` is the transaction time, which the database also assigns.
  - `load` rebuilds `PolicyHistory`. It recomputes every content hash and receipt hash, and checks the label, tenant, version sequence, and the receipt's limits and exclusions against the draft. It re-applies the domain's admissibility rules (no blocking conflict, no limit gap, acknowledged codes equal to the open conflicts). Any mismatch raises `PolicyStoreError("integrity")`. Tamper detection does not cover a hostile qw_app that recomputes the hashes; that needs C-20 signing.
- `apps/api/src/qw_api/policies.py` (new; registered in `app.py`)
  - `GET /policies`: C-02 page with the T010 HMAC cursor, page size ≤ 100.
  - `GET /policies/{id}`: the latest version, with `ETag "N"`. Any member can read.
  - `POST /policies/{id}/adopt`:
    - requires tenant_owner, a step-up within `Settings.step_up_window` (401), CSRF and Origin (403), an Idempotency-Key (C-03 replay or 409), and If-Match `"N"` (428 if absent, 412 if stale or the hash differs);
    - returns 400 `revision_mismatch` when If-Match, `expected_revision` and `version_id` disagree (C-04);
    - returns 409 `already_adopted`, or 422 with the domain code (`unacknowledged_conflict`, `limits_required`, ...);
    - rejects an acknowledgement over 4096 UTF-8 bytes (the 0009 CHECK) with 400 `/acknowledgement`;
    - writes the audit event `policy.adopted`. `audit_event` has no details column, so the version and receipt hash are not in it.
  - Another tenant's id and an unknown id get byte-identical 404s, apart from the correlation id.
  - Bodies follow `policy.schema.json`. Values are decimal strings and `accepted_at` is UTC `Z`.
- Tests:
  - `packages/adapters/tests/test_policy_store.py` (new, 8 tests);
  - `apps/api/tests/test_policies_api.py` (new, 3 tests; includes paging at limit=1);
  - `test_tenancy.py`: the 0009 tables were added to the forced-RLS list;
  - `test_api.py`: the operation count went from 8 to 11.

## Owner decisions needed (implementer interpretations; review does not settle them)
Each of these is an owner decision: the `acknowledged_conflicts` extension, the placeholder freshness and loss-pause ids, the dropped limit window, owner-only adoption, and 412 instead of 409 together with `"N"` instead of C-04's `"r<N>"`.
- **Contract extension.** `AdoptVersion` gains `acknowledged_conflicts: [ConflictCode]`. The spec body has only free text, and C-20 says free text never authorises. The domain requires each open conflict to be acknowledged by code. This also needs a project-contract entry (A-01; `contracts/` does not exist yet).
- **Response mapping** (no field of the schema left out):
  - `goal` is the ONB04 objectives joined by `,`.
  - `horizons` are the domain's kept horizons, with `same_day` mapped to `intraday`.
  - `unit` is `ratio` or the scope currency (matching the `risk_policy_draft.json` `limit_format`).
  - `scope_id` is `account:currency[:sleeve]`. The limit `window` has no field in the schema, so it is not returned.
  - `permitted_catalogue_ids` and `adopted_strategy_version_ids` are `[]`, which is fail closed.
  - `data_freshness_policy_id` and `loss_pause_policy_id` name the spec config versions (`feed_and_freshness_policy:0.1.0-design`, `risk_policy_draft:0.1.0-template`), because no such policy records exist.
  - `tenant_id` is returned, as the schema requires; C-07 only permits omitting it. It is the caller's own tenant.
  - The responses have no FastAPI response model, so the T010 contract test (no `tenant` key in any request or response model) is unchanged.
- **Who adopts.** Only tenant_owner may adopt; members may read. The spec names no role, so this is the conservative choice.
- **Status codes.** A stale If-Match gets 412, as in T010. The openapi text says 409 for stale values; C-04's form `"r<N>"` is likewise not used yet (T010 kept `"N"`).
- **Status values.** Status is derived by the domain. `paused` is never produced, because pause persistence does not exist yet. A version older than the adopted one reads `superseded`, even if it was never adopted.
- **List queries.** The list reloads each history (N+1 queries per page, page ≤ 100).
