## Changes
- `packages/domain/src/qw_domain/onboarding.py` (new, PR A)
  - `load_catalogue` binds the config to typed response schemas (`onb-responses/1`). Any drift in the config is rejected: ids, order, version or flags.
  - Answer kinds:
    - choice, unordered multi, ranked (ONB04), ids, ratio, date;
    - money `{amount, currency}`;
    - dated money (`ONB06.need`);
    - allocations per (account, currency, sleeve) (ONB13);
    - limits `{metric, value, unit ratio|amount, denominator, account_id, currency, sleeve_id?, window}` (ONB14).
  - Numbers are decimal strings only, positive, within the `Ratio`/`MoneyAmount` bounds.
  - Duplicate metric+scope or duplicate allocation scopes are rejected.
  - Conditional visibility:
    - `ONB04.target_return` shows for growth or active trading;
    - `ONB05.goal_date`;
    - `ONB06.need` shows for a known dated need;
    - ONB17 and ONB18 show only when AI is enabled.
    - An answer to a hidden question is rejected (`hidden_question`).
  - `not_sure` is accepted for any question except ONB21. ONB21 is never a response (`adoption_is_explicit`).
- `packages/domain/src/qw_domain/policy.py` (new, PR B). This section and the `test_policy.py` entry describe PR B and apply once it lands.
  - `build_draft`:
    - Each `InferredField` lists the response ids that support it.
    - Limits are the user's ONB14 entries verbatim. No template and no ONB07 answer ever fills them, so with no entries the limits stay empty (null).
  - Contradiction rules (spec §2). Each produces a visible `Conflict` and nothing is averaged.
    - Preservation + near-term essential withdrawal + intraday or active trading is blocking: adoption fails until the answers change.
    - Monitoring below regular-session excludes `horizon:intraday`.
    - Options off + an existing short option: exclusion `new_option_ideas`, with `option_risk_and_expiry:<acct>` kept as a retained warning.
    - Unknown option permission on an account excludes `option_proposals:<acct>`.
    - A profit goal gives a feasibility warning. It is checked against a caller-supplied reviewed `FeasibilityBound`; the module sets no number. Without a bound it gives an "unassessed" warning.
  - `PolicyHistory`:
    - Append-only versions and receipts.
    - `propose` adds a version only when the content hash changes.
    - Status is derived (`adopted` / `superseded` / `awaiting_adoption`). The adopted version is never edited.
    - Only the latest version can be adopted.
  - SYNTHETIC label: set for ONB01 `hypothetical_only` or when `synthetic=True`.
  - `adopt` produces a typed `AdoptionReceipt` (C-20 `kind=policy_adoption`) with:
    - principal id;
    - step-up receipt id;
    - signing time (UTC);
    - policy hash;
    - label;
    - the exact limits (value, unit, denominator, currency, scope, window);
    - acknowledged conflicts;
    - exclusions;
    - acknowledgement text (recorded only, never authorises).
    - `receipt_hash` is SHA-256 over canonical JSON.
  - `adopt` fails on any of:
    - a blocking conflict;
    - unacknowledged or unknown acknowledgements;
    - no limits;
    - any allocated scope missing one of the six `risk_policy_draft.json` metrics (`missing_required_limits`);
    - a missing principal or step-up id. Free text or accepting recommendations cannot adopt.
  - `check_sizing` returns allowed/blocked with typed `SizingBlock` reasons. It blocks on:
    - no adopted policy;
    - a SYNTHETIC policy;
    - a tenant mismatch;
    - a receipt/version hash or limit mismatch;
    - a missing account, currency or denominator;
    - a scope that is not allocated;
    - a missing required limit for the scope (account-wide limits cover that account's sleeves in the same currency only).
- `packages/domain/tests/test_onboarding.py` (new, 22 test cases: 4 tests plus 18 parametrized rejections).
- `packages/domain/tests/test_policy.py` (new, 16 tests, including one Hypothesis property).
