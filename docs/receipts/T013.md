## PR A — accounts, versioned mapping, consolidation
- `packages/domain/src/qw_domain/sources.py` (new)
  - `UnderlyingAccount` is separate from `Source` (`SourceKind`: broker API, broker export, aggregator, manual, mirror).
  - `SourceMap.remap` appends a `MappingRevision` per (source, reference): half-open intervals, each naming one account of the source's tenant, no overlaps, knowledge time non-decreasing, validated before anything changes. `resolve(..., known_as_of)` replays earlier revisions; history is never rewritten.
  - `consolidate`: snapshots after `as_of` ignored; unknown source or no mapping in force is quarantined; another tenant's source is refused (`foreign_tenant`). Per (source, reference) only the latest snapshot counts; older than `max_age` is stale and supplies no figure. Authority `source_authority/1`: broker API > broker export > aggregator > manual > mirror; the top fresh candidate supplies the figure. A complete snapshot reports an omitted item as 0; an incomplete one is silent.
  - Status: `conflicted` (fresh sources disagree, or a stale source of higher authority than the one used last reported a different figure; the `ItemConflict` lists every candidate, stale ones flagged), `incomplete` (no fresh complete snapshot backs the account), `stale`, `no_data`, `reconciled`. All but `reconciled` block sizing.
  - Cash basis is `broker_available` only from broker/aggregator sources. Docstring limitations: no field-specific precedence; aggregator cash needs per-provider qualification.
