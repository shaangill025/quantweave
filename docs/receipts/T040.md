## Decisions (Part A)
- **Mode (R023).** The mode stays the adopted policy's `ai_mode` (`proposals.policy_mode`); no routing function takes a mode argument (a test checks `submit`'s signature). It changes only through policy adoption, a step-up consent; `mode_changes` lists each change with principal, step-up receipt, time and receipt hash. A version binds the policy hash, so after a mode change an in-flight candidate fails `POLICY_CHANGED` and is invalidated; it is never moved to the other mode's path or relabelled. A gateway or budget refusal never touches the policy.
- **One entry, all origins (R015, R019, R023).** `submit` moves candidate → verifying, then re-checks every claim against evidence frozen at the decision time with `researcher._problem`. A failure rejects with `MATERIAL_CLAIM_UNSUPPORTED` and per-claim details. Then AI mode sends rule, research and chat candidates to `awaiting_review`; rules mode sends rule candidates to `ready_for_final_check` (`rules_verified`) and AI or chat candidates to `research_only` (`NOT_AI_MODE`). `submit` refuses a version whose tenant, instrument, id or strategy differs from the mandate.
- **Rule origin cannot be forged (review S1).** A rules-origin `Candidate` carries its `Fact`/`Calc` inputs; its thesis must equal `rule_thesis` of them and its record must equal the run-free `rule_record`. A model thesis wrapped in a rule mandate, a dropped claim, or a record with model runs is refused (`rule_thesis`). `evaluate` independently refuses a rules-origin thesis with leads, other alternatives, or any claim that is not a reported fact or a formula calculation (`rules_thesis`).
- **Calculation claims (R023, R085).** Each input is a reported fact citing its passage; each calculation names a registered formula over input passages in order. The claimed value, times 1e18, must equal the exact (`Fraction`) result rounded half-even to an integer count of 1e-18 units; no decimal context is involved (review N3). Repeated input passages (N4), social inputs, other entities, mixed attribute or unit, unknown formulas and wrong arity are refused. A model cannot name a formula, so model-written calculation claims stay `kind_unsupported` as in T038.
- **Evaluator hand-off.** Rule-origin reviews use the T039 passes; `isolation` is `rules_origin`, `model_family_distinct` is false, `researcher_run_id` is `rules:<mandate>`; the distinct-family check is skipped because there is no proposer model. `apply` requires the review to bind proposal id, version and thesis hash and to be completed no later than the decision time. Approve → `ready_for_final_check` (T026 final check still decides); revise → `REVIEW_REVISE` event; research-only / reject → recorded with codes; abstention → `REVIEW_UNAVAILABLE` event, candidate stays pending.
- **Labels.** `ai_reviewed` needs a bound approving review on the latest version, not just the state.
- **Deadlines (R067, R074).** `deadline` = min(expiry, original trigger + review window), the window capped at 60 s for intraday. `sweep` (and `apply`, first) expires a candidate still awaiting review at the deadline with `REVIEW_DEADLINE_MISSED` (`review_missed`). `resubmit` (the one revision, bounded by T026) refuses a changed trigger, origin or window and reruns the claim checks. `tally` counts every label, misses included.

## Negative and adverse cases (Part A, SYNTHETIC)
- Oracles: closes 100, 105, 110 → momentum 0.1, mean 105 (hand-computed). Wrong value, swapped inputs, unknown formula version, one input, an unread passage, a revenue passage as input and a repeated input (claimed 0) are each rejected with the exact per-claim code in both modes. A social close yields `f-c0:lead` and `social_input` for both calculations.
- Forged rule origin (review probe pc.py): an AI thesis in a rule mandate, a dropped claim and a record with runs raise `rule_thesis`; `evaluate` on the AI thesis with a rule mandate raises `rules_thesis`.
- AI mode: publication before review is refused (`NOT_READY`); a contested calculation verdict gives `revise`; a forged thesis hash raises `review_binding`; a review dated after the decision time raises `review_time`.
- Outage: an unqualified evaluator route abstains `gateway_refused`; the candidate stays `awaiting_review` with a recorded event; the mode stays AI; one second before the deadline nothing changes; at the deadline it expires `REVIEW_DEADLINE_MISSED` and `tally` counts it. A complete review applied after the deadline is a miss.
- Mode change rules → AI invalidates a rules-verified candidate at publication; AI → rules invalidates a pending one even with an approving review. A caller-supplied mode is refused by `Proposal.new`.
- Import boundary: routing and chat reach evaluator and proposals but no commitments, reconciliation, broker or order module (journal and postings only read, via valuation).
