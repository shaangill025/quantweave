## Negative/adverse cases
- `check_contracts.py --self-test` injects 16 defects, each detected:
  - routes: an `/accounts/{id}/orders` broker route, a disguised `/accounts/{id}/positions/close`,
    `/connections/{id}/liquidate` under a harmless operationId, an unlisted neutral-named account
    mutation, and an operationId renamed to `cancelOrder` on an allowlisted path (the allowlist is keyed
    by method, path and operationId);
  - simulator `broker_submission` flag removed;
  - missing Idempotency-Key;
  - decimals: `number` money, `integer` quantity, the `Decimal` `$ref` target loosened to `^.*$`, an
    inline `number` query parameter, a money-named integer query parameter, a plain-string money field in
    an inline request body;
  - timestamps: offset-less, `-00:00`, an impossible date (`2026-02-30`).
- Adversarial readings from review, not tests: C-09 open redirect, C-10 archive paths, C-16 backdated
  simulated orders, zero quantities in live legs, C-20 free-text consent.
- **Remaining limits of the check:**
  - money fields are found by property or parameter name, so `pnl`, `nav`, `premium` or other unusual
    names are not checked;
  - timestamps are checked only in the contract examples, and only under keys ending `_at`. Schemas are
    not checked for the offset rule, because 0.1.0 has no pattern to check (C-05);
  - accepted decimal patterns are the two 0.1.0 generic patterns. The per-class patterns of §3.2 are
    adopted when the project contract exists (A-01);
  - the broker allowlist covers the 0.1.0 surface. Any new account, connection or trading-verb mutation
    fails until it is reviewed and added.
