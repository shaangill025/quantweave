Conventions:
- Value = quantity x mark x explicit multiplier (no default); reporting = local x rate. Exact `Fraction` products, rounded once toward minus infinity at 1e-12 (assets down, liabilities away from zero), so value and unrealized gain are never overstated.
- Unrealized = value - remaining average cost (`postings.LOT_POLICY`). In the reporting currency it needs `cost_reporting` (cost at historical rates). `cost_reporting` is caller-trusted: it is not cross-checked against the journal or any FX history. Realized P&L is the journal's, per currency, untranslated.
- `Unavailable`, never zero: missing, non-positive, stale or future mark or FX; missing multiplier; unsupported short; unknown cost; an account with no journal rows (`account_unknown`). NAV is unavailable if any part is; the available total is labelled partial.
- Staleness: an input is fresh while age <= `max_age` (equal is fresh, one microsecond more is stale). The spec gives no boundary; this is an implementation choice.

## PR B — returns
| Path | What |

| `packages/domain/tests/test_returns.py` (new) | 33 tests. |

Conventions (the module docstring has the detail):
- TWR links exact sub-periods at flows; half-even at 1e-18. Missing valuation, non-positive start, negative end value (`negative_end_value`), equal or decreasing times: `Unavailable`. An end value of exactly 0 is -100%.
- MWR solves sum(CF_i y^d_i) = 0 with y the daily discount factor (integer powers only), ACT/365F annualization for horizons >= 365 days or on request.
  - Unique root when the net flows change sign once (Descartes), or when the partial sums from the start and from the end change sign once in total, with a positive last flow (Laguerre's bound; Norstrom's criterion alone only rules out a second root with r > 0, so the sums from the end are also checked).
  - Otherwise `ambiguous`, with candidate roots from a 5% grid and no single value.
  - A zero terminal value after contributions only is a total loss: -100%, `uniqueness_rule` `total_loss`.
  - `growth_domain` for 1 + p defaults to [1e-6, 1e6] and is a parameter. This range is an implementation choice, not from the spec.
  - Bisection to 1e-30 in y; hitting `MAX_ITERATIONS` warns `not_converged`. `residual` is at the unrounded solver root, not the 18-place `Ratio`.
- FX: interaction rounded half-even; local + currency + interaction = reporting.

Conventions (module docstrings have the detail):
- **Benchmark.** The opening value and each net flow of a date trade at that date's level; `Execution` has this one member and any other value (e.g. `next_close`) is rejected. A missing level on the start, a flow or the end date gives `benchmark_level_missing`, also on a date whose flows net to zero. Nothing is carried forward or interpolated: the spec defines no fill policy, so none is applied.
  - The policy pins `series_version`; a different series version gives `benchmark_version_mismatch`. Reinvestment is declared: `total_return` for an index (distributions are in the level) and `none` for a proxy (price levels; distributions not modelled). Any other combination is rejected.
  - Flows must fall in [start, end); others give `flow_outside_period`. The opening value is the value at the start of the start date and the ending value is at the end date's level, so V_start, V_end and the flows share one convention; a portfolio compared against the benchmark must be valued on the same convention (also stated for Modified Dietz).
  - A total-return index buys fractional units at no cost. An investable proxy buys whole multiples of `unit_increment`, which is restricted to a power of ten (1, 0.01, 10, ...; 0.5 is rejected), pays `fee_per_trade` on each trade and keeps residual cash at zero return. A withdrawal sells the fewest units that cover it and the fee.
  - Negative units give `negative_units`.
  - The policy must be selected before the start date begins anywhere (00:00 at UTC+14), else `benchmark_selected_late`.
  - TWR is computed on exact simulated values; fees are internal performance effects. MWR is computed on the opening value, the net flows and the ending value. The ending value and units are floored at 1e-12.
  - Single currency only: the policy, series, opening value and flows must share the reporting currency (`CurrencyMismatchError`).
- **Modified Dietz** (`modified_dietz_approx/1`) returns an `ApproximateReturn` labelled "approximate (Modified Dietz), not exact TWR".
  - Formula: (V_end - V_start - sum CF) / (V_start + sum w CF), with w = (D - d)/D on calendar days and flows at the start of their day. A flow on the start date has weight 1; one on the end date has weight 0.
  - Exact `Fraction` arithmetic, rounded once half-even at 1e-18.
  - A denominator ≤ 0 gives `nonpositive_denominator`; a zero-day period gives `incomplete_period`.
- **Linked FX** (`fx_multiplicative_linked/1`) covers pathwise sub-periods of one local currency, with flows only at their boundaries. The product of (1 + r_reporting) over sub-periods factors into the chained local return times the chained FX return. So the linked local and currency effects are the chained returns, and the interaction is their product; the sub-period attributions are kept. The spec defines no convention for allocating the currency effect across several currencies or accounts, so that is not implemented.
- **Dates.** `DatedFlow.on` and `ExternalFlow.on` are calendar dates in the account's reporting calendar. The caller converts event instants with the account's declared zone. The spec does not define this basis.
