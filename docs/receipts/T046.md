### Rules
- **Closed knob set.** `ADAPTABLE` has exactly six keys: `extract.publication_date` (`updated_else_published` v0, `published`, `first_date`), `extract.value` (`first_number` v0, `last_number`), `retrieval.match` (`attribute_period` v0, `attribute`), `retrieval.ranking` (`primary_first` v0, `recency`), `retrieval.top_k` (1 to 5) and `prompt.template` (from `PROMPTS`). Any other key is refused, never ignored: `widens_authority` when it names the evaluator or assessor, risk or policy, thresholds or scorecard, answer keys, holdout or split, rights, freshness (`fresh`, `max_age`, `stale`), budget or cost, approvals, release or signing, tools, consent, tenant or scope, orders or brokers, secrets or keys; otherwise `not_adaptable`. Values are parsed strictly and canonically.
- **Producer (rules v0).** `propose` reads only a `development` fixture and, for each extraction knob, keeps the registered rule that reads the most development documents correctly (ties keep the current rule). A `promotion` fixture is refused (`not_development`). `candidate` wraps the configuration as a T044 `Candidate` whose artifact hash is the configuration hash.
- **Protocol.** `check_protocol` requires target `research` and a scorecard holding `false_references`, `lookahead_uses`, `scope_widening` and `payload_invalid` as hard `at_most 0`, besides T044's `unsupported_material_facts` (`control_missing`). `scorecard` adds goals: `pub_date_gain` ≥ 1, `answer_change` ≥ 0, `cost_usd` ≤ the owner bound, `model_calls` ≤ the owner bound.
- **Frozen fixture and answer key (R084).** `Fixture` holds labelled documents (raw text with answer-key publication date and value) and point-in-time cases (question, `as_of`, freshness limit, answer or "abstain", correct references), a split and an evidence class. Its `content_hash` must equal the T032 plan's `protocol_hash`, which T044 freezes into the protocol through `plan_digest`. Changing any answer, date or reference is `answer_key_changed`; another plan is `test_access_changed`; a development fixture is `not_promotion`; a relabelled evidence class is `evidence_class`. A fixture with no document published after some case time (`fixture_no_lookahead_trap`) or no document for another period (`fixture_no_reference_trap`) is refused, because the hard controls would be vacuous on it (the T045 S1 lesson).
- **Controlled evaluation (`measure`, run by the assessor).** For the frozen baseline and for the candidate it:
  1. extracts each document's publication date and value; an unread document is never ingested with a guess;
  2. ingests the rest through the T036 `EvidenceStore` (T023 ingest rights, quote-span and value-in-quote checks);
  3. retrieves the passages whose extracted publication date lies inside the case window `[as_of − max_age, as_of]`, matching the question as configured, ranked, top-k;
  4. runs the real T038 `research` loop on them through the T037 gateway (admission, budget reservation, snapshot, read-only tools, strict claim checks).
  Against the answer key it counts `pub_date_correct`, `value_correct`, `answers_correct` (the case answer with only listed references, or an abstention where none was published), `unsupported_material_facts` (each supported reported fact whose value is not the case answer), `false_references` (each cited document the key does not list; an `unsupported_claims` abstention also counts one), `lookahead_uses` (each retrieved passage truly published after the case time), `model_calls`, `cost_usd` and `run_failures`. A payload edited around the constructor scores `scope_widening` per stray key and `payload_invalid` per bad value; the remaining knobs are replayed. The metrics reach a verdict only as the assessor's T032 promotion trial read by T044 `assess`.
- **Promotion (T051).** The candidate has no promotion path of its own: an AST test checks that the module defines no promote, approve, install, adopt or sign function. An accepted installation-scope candidate is released by a maintainer through `prepare_release` (producer and assessor refused as `self_approval`), signed, and installed by an operator. `config_of` returns the configuration a signed research release names, and refuses `artifact_mismatch` unless configuration hash, candidate artifact hash and manifest artifact hash agree. Tenant-scope research protocols cannot be released (`tenant_scope`).
