## Negative/adverse cases (SYNTHETIC)
- **Minimal payload.** A proposal (buy 80 at 50, 4000 CAD, acct-1), an alert ("close 99.5 -> 100.25") and a risk pause are rendered for email and push. Title and body contain no quantity, amount, price, currency, side, account, instrument, proposal, watchlist, rule or pause id, tenant, user or address, and no digit at all. The link is exactly `/notifications/ntf-<32 hex>`.
- **Late notification.** One resolver is built at AT and reused. Opened at AT+1 min, the proposal is `active` and actionable. At AT+31 min it is `expired`, not actionable, with current version `1:expired` and event age 31 min; also at AT+45 min. The proposal's events are unchanged, so opening never acts.
- **Superseded, missing, mismatched.** A revised proposal opens its version-1 notification as `superseded` (current `2:candidate`). A missing object opens as `unavailable`. `subject_mismatch` is raised for: another proposal; forged versions `3:active`, `x:active` and the empty string; a job-category subject with the proposal's id; another tenant.
- **Sending is not reading.** Email and push are delivered, yet `seen_at` stays empty, including after a feed listing. The first open sets it, and a later open keeps the first time.
- **Dedupe and retries.** An outbox redelivery returns the original record, `created_at` and `trigger_at`. A trigger 6 min later creates a feed item but its sends are `coalesced`; one 10 min later queues both channels.
- **Delivery state.** Rejected, rejected, accepted gives 3 attempts and `delivered`, accepted 33 s after the trigger, with `created_at` unchanged (R067). A transport exception gives `unknown`/`transport_error` (its text is not stored); a non-enum result gives `unknown`/`unrecognised_result`; both are final. Also refused: `not_retryable` after delivery or `unknown`, `attempts_exhausted`, `time_order`, and `no_delivery` for another user or tenant.
- **Re-check at attempt.** No message is sent and the delivery closes (`failed`, 0 attempts, then `not_retryable`) when, after queueing, push is revoked, push is opted out, email becomes unverified or absent, the category is muted, or the push subscription expires at the attempt time.
- **Quiet hours.** America/Toronto, windows 22:00-07:00 and 12:00-13:00:
  - a signal at 03:00 EDT is deferred to 07:00 EDT, and an earlier attempt is refused;
  - start is inclusive and end exclusive; DST is handled (23:00 EST in December);
  - chained windows 22:00-07:00 and 07:00-08:00 end at 08:00;
  - refused: equal start and end, `7:00`, `24:00`, an unknown timezone, a list instead of a tuple, and windows covering the whole day.
- **Safety (D1).** Risk-pause email and push are not deferred by quiet hours, and a second pause, or a new version of the same pause, inside the window is not coalesced. An alert at the same time is still deferred.
- **Validation.** Refused email addresses: a CRLF `Bcc:` injection, a space, two `@`, no dot in the domain, a local part over 64 characters, over 254 characters in total, and non-ASCII. Refused endpoints: a CRLF, no host, a space, `ftp://`, DEL, over 2048 characters. Also refused: non-bool flags (`"no"`, `"false"`, `1`), a list or untyped `muted`, an unknown permission, a short `id_key`.
- **Atomic submit, resolver errors, isolation.** An exception mid-decision stores nothing, and a retry creates the record with both deliveries. A failing resolver lists items as `unavailable` in the feed; `open` raises and records no `seen_at`. Opening before creation is `time_order`. Other users get `not_found`, and another tenant's signal or recipient is refused. A different `id_key` gives a different id.

## Review
- Reviewer: a subagent running a different model from the implementer, two rounds.
- Round 1: REQUEST CHANGES.
  - S1: `attempt` sent without re-checking consent or qualification.
  - S2: the resolver clock was decoupled from the open time, so a late open showed an expired proposal as active.
  - S3: email addresses and push endpoints were unvalidated (header injection).
  - S4: `submit` was not atomic.
  - S5: transport exceptions were retried, risking duplicate sends.
  - S6: preference flags were untyped.
  - All six were fixed; each single-fix revert fails its test.
- Round 2: APPROVE.
  - The reviewer probed: withdrawn sends; a late open at +45 minutes; a wide malformed address and URL set; exception and unrecognised outcomes; the D1 bypass keyed on category only; `id_key` validation; subject mismatch; feed error mapping; time order.
  - All five checks passed (1737 passed, 0 skipped).
- Round-2 nits, not changed (the PR is near the size cap), recorded as remaining work:
  - n1: a non-conforming transport that returns the plain string "accepted" is recorded as delivered. Typed transports are checked by mypy. The SMTP and Web Push adapters must return `SendOutcome` members, and an `isinstance` check should be added with them.
  - n2: the address pattern accepts consecutive or edge dots and edge hyphens, which is harmless for header safety. Tighten it with the SMTP adapter.
  - n3: the push sender must add an SSRF guard (resolve the host and deny private, link-local and metadata ranges) and a port range check.
  - n4: `feed` maps every resolver exception to unavailable. Add an internal error code when logging exists.
  - n5: a `withdrawn_*` delivery is final, so re-enabling a channel does not resend it. This is intended and fail-safe.
  - n6: D1 (risk_pause email and push bypass quiet hours and coalescing) stays an unresolved owner gate until confirmed.
- Outcome: approved. The reviewer's approval is evidence, not authority.
