### Rules (decisions an owner or reviewer may challenge)
- **Contract.** It is followed exactly. There is no edition, brand or installation field, so one format serves both editions (R006, R013, R097). The source edition and record counts are gaps, not added fields. C-10 is enforced in code; a schema amendment needs the owner.
- **Versions.** `qw-export-<major>.<minor>`, where `compatibility_version` is the oldest reader that can import. A newer minor is a downgrade: unknown sections are size- and hash-checked, and `.json` ones are also scanned, including for denied ids. They are listed as unsupported and never loaded.
- **Structural allowlist.**
  - **Open sections:**
    - the five T052 learned-state files, with closed key sets per record type derived from the T052 types (`records.json` chosen by `record_kind`, with `subject`, `fact` and case `inputs` nested);
    - `research/evidence.json`, contract Evidence: the exact 13 keys including `coverage`, field types checked, unique `id`s, and tested against `project_contract.schema("evidence")`.
  - Every object is checked recursively; an unknown key, or an object under a scalar, gives `unknown_field`.
  - **Closed** (`section_not_ready`, on export and import): journal, accounts, policies, watchlists and tombstones. Each opens with its store's export function and schema.
  - Key-name and prose heuristics are removed.
- **Value scan.** Defence in depth for high-confidence formats only:
  - PEM in any case (whitespace allowed), and base64 PEM at all three byte offsets;
  - JWTs; `ssh-*`/`ecdsa-*` followed by `AAAA`;
  - AWS `AKIA`/`ASIA`, `gh[opsur]_`, `xox[bap]-`, `[rs]k_live_`, `sk-ant-`, long OpenAI `sk-`/`sk-proj-` (32 or more characters), Google `AIza`, `npm_`, Slack webhooks;
  - URL credentials; `Bearer` tokens of 16 or more characters that contain a digit; `Basic` only when the base64 decodes to a `user:password` (so `Basic 1234567890123456` passes).

  **Free-text fields can still carry anything the scan misses.**
- **Factories.** No seal field: the constructors raise, so `dataclasses.replace` and `copy.replace` fail. A decision whose fields are tampered with, or that is empty, gives `decision`.
- **Licensed evidence (spec §6).**
  - **What a decision records.** Each item's `check_use(user_export)` outcome with its `feed_hash` and `entitlement_hash`, the scope, `at` and jurisdiction, and one omission per denial: `rights:<all deny codes, '.'-joined>:<id>`. Its `decision_hash` covers all of these.
  - **What `build_export` refuses.**
    - A decision for another scope, made after `created_at`, or older than `DECISION_MAX_AGE` (10 minutes).
    - An evidence `id` that is not permitted (`evidence_undecided`).
    - A record whose `rights_profile_id` is not the feed its item was decided on (`evidence_feed_mismatch`). The binding uses `rights_profile_id` because T036 serves the T021 feed id there (`qw_api/research.py`); `source_id` is the T036 source.
    - A denied id in any string value of any section (`evidence_omitted`, checked on import too).
  - **Token rule.** Matching is case-sensitive and unnormalised. An id of 6 or more characters, or of 3 or more mixing letters with digits or punctuation, matches when not preceded or followed by a letter, digit, `_` or `-`: `ref:evd-2`, `evd-2:1` and `evd-2.json` match, but `evd-20` and `x-evd-2` do not. Other ids match only an exactly equal value, because the contract sets no minimum id length and a word-like id (`a`, `data`) would otherwise match prose.
  - **Why 10 minutes.** The decision is made in the same export job, just before the build.
  - **GATE** for the export job increment: the route sets both `at` and `created_at` from the server clock.
- **Import is inert (R051).** Nothing is adopted, activated or reauthorized.

### Rules
- **Writer.** It accepts only an `ExportBundle`, which only `build_export` makes. The layout is `manifest.json`, then files in path order, deflated, mode 0644, fixed timestamp, no extra field or comment, so the same bundle always gives the same bytes. The writer reads its own output back under the same limits.
- **Reader.** Before decompressing anything it checks:
  - size and entry count;
  - per entry:
    - encryption flags;
    - any flag except deflate options and UTF-8 names (`entry_unsupported`);
    - extra fields;
    - symlinks, directories, special entries and executable bits;
    - methods other than stored or deflated;
    - C-10 paths;
  - declared sizes, the ratio above the floor, and duplicate and case-folded names;
  - **layout** (`archive_layout`): local records from offset 0, back to back, then the central directory, then a 22-byte end record that ends the data. This refuses prepended and appended data, polyglots, comments, gaps, overlaps and ZIP64;
  - **local headers** (`local_header_mismatch`): each must equal its central-directory entry.

  Entries are then read with a bound (zipfile stops at the declared size and checks the CRC). Finally the domain `verify_import` runs.
- **Ratio trade-off.** At 100x, repetitive legitimate JSON could be refused, so the ratio applies only above 1 MiB. The size limits bound inflation regardless. Tests show 0.5 MiB of spaces accepted and 2 MiB refused.
- **Windows names.** Reserved names (`CON`, `aux.json`) and trailing dots pass, because nothing is extracted to disk. T058 and T060 must check them before any extraction.
