### Rules
- **Records.** `Feedback`, `ErrorRecord`, `Outcome` and `EvaluationCase` share tenant id, record id, a `Subject` (kind, object id, version, content SHA-256), the source time `occurred_at` and `recorded_at` (aware UTC, recorded not before occurred). The store is append-only with a per-tenant clock. An identical retry returns the stored record and its original times. Different content under the same id is refused (`conflicting_duplicate`). A deleted id is never reused.
- **Feedback.** Categories are the contract's six (`incorrect_fact`, `irrelevant`, `clear`, `unclear`, `missed_risk`, `other`); message at most 4000 characters. The contract fixes `cross_user_contribution_consent` to false, so the record has no consent field at all. Thumbs ratings are not in the contract and are not added.
- **Errors.** `errors_from` turns a T039 outcome into records: an `Abstention` gives `abstention:<why>`; each material ground of a `Review` gives `evaluator_disagreement:<prefix>`; each rejected evaluator claim gives `model_error:claim_rejected`. Details are codes, not prompts or responses. Ids derive from content and the source time, so a retry maps to the same records.
- **Outcomes (spec §7, §14).** `Disposition`: dismissed, expired, invalidated, superseded, rejected, research_only, planned, user_reported, broker_confirmed, reconciled, virtual_filled. `Result`: not_applicable, unknown, gain, loss, flat.
  - Without an execution (the first seven, including planned), the result must be `not_applicable` and there is no fact. A dismissal therefore cannot be stored as a losing or winning trade.
  - An executed disposition needs a result other than `not_applicable`. Gain, loss or flat need a `FactRef` of the matching kind: `execution_report` for user_reported, `journal_event` for broker_confirmed or reconciled, `virtual_entry` for virtual_filled.
  - `basis` (none, real, virtual) is derived from the disposition, never supplied, so a virtual outcome is always labelled virtual. `tally` counts by (basis, result) and never merges bases.
  - `outcome_of` reads a T026 proposal version's own history. It infers no result. A live version (no terminal state, nothing planned) is refused (`live`).
  - Outcomes are categories only. No P&L amounts are copied.
- **Consent (R031, spec §12).** `Purpose` has only `personal_adaptation` and `shared_improvement`; there is no live-decision purpose.
  - Personal adaptation takes the tenant's own records with no consent.
  - Shared improvement needs a `ConsentGrant` from that tenant (and, after round 1, from the feedback's own principal) for the named recipient and terms version, covering the record's kind, granted by the selection time, not expired (exclusive) and not revoked. Otherwise the record is excluded with `no_consent` or `category_not_consented`. Default deny.
  - Revocation is prospective. Later selections exclude the records. Earlier `Use` entries stay, and `affected_uses` flags them (`consent_revoked`) so derived state can be invalidated or rebuilt.
- **Selection is the enforcement point.** `select` returns the eligible records and a reason for each one withheld, and logs every call as a `Use`, even an empty one. It sees only the calling tenant's records.
- **Evaluation cases (R040, R084).** Inputs are limited to `CASE_FIELDS` (instrument id, attribute, period, unit, claim kind, as-of, feedback category, error code, evidence digest, proposal hash). Digests must be SHA-256 hex, not content. Account ids, quantities, prices, cash and free text are refused (`field_not_permitted`). Inputs are frozen, and `case_hash` covers subject, inputs, expected label, split and origin.
  - `CaseOrigin.SYNTHETIC` reports `personal_history` false.
  - A `final_holdout` case is never given to `development` access. `final_assessment` takes only final-holdout cases, each at most once per experiment (`holdout_reused`).
- **Deletion (R052, R087).** `delete` writes a `Tombstone`, drops the content and makes the id unreadable. Uses that took the record are flagged `record_deleted`.
- **No live path.** The module imports only types from `proposals`, `evaluator` and `researcher`. A test parses its AST and finds no reference to proposal mutators, evaluator calls or gateway adapters.

## Negative and adverse cases (SYNTHETIC)
- Shared selection with no grant, after revocation, before the grant, at expiry, for another recipient, under other terms, for an unconsented record kind, or with another tenant's grant: excluded.
- Another tenant: personal and shared selections return nothing; `get`, `revoke` and `delete` raise `not_found`.
- Dismissed and expired proposals: `not_applicable` result, no basis, bound to the version's content hash. Forcing loss, gain, flat or unknown onto them is refused. Planned is not an execution.
- Grant refusals: personal purpose, empty categories, a changed grant under an existing id, double revocation, backdated revocation. Selection refusals: shared without recipient and terms, personal with them.
- Records: changed content under an existing id, backdated record, recorded before occurred, naive time, a category given as a string, a message over 4000 characters, a malformed subject version or hash.
- Cases: `account_id`, `quantity`, `cash`, `price`, `message` and `prompt` inputs refused; a passage text in `evidence_digest` refused; frozen inputs cannot be mutated.

## Interpretations and gaps
- The spec defines no outcome-category list. The categories here come from the proposal states and execution states in spec §7 and the virtual ledger in §14. The owner may want to review them.
- Licensed third-party content inside a record (for example a quoted passage in a feedback message) is not rights-checked for shared use. That needs the T021 rights check and an authorised transformation before export; a deferral, not a pass.
- `affected_uses` flags derived state. It does not delete trained derivatives; that belongs to T044+ and to retention policy.
- R028 and R029 (six improvement paths, scorecards) are only prepared for: records carry kinds, splits and access logs for T044+ to consume. R087 archive import is not addressed.

A cross-model reviewer requested changes. Each new test failed against the round-0 code; that was checked by running the updated test file before changing the module (6 failed, including the two consent tests that use `covers_prior`).
- **S1, raw model text in error details.** `Abstention.details` can carry model query text or exception text. Each `; `-separated part is now kept only if it fully matches `ID_PATTERN` (a code of at most 128 characters); anything else becomes `redacted`. Tested with "AAPL position 1500 shares at account 99-123 ..." and a 129-character part.
- **S2, `get` bypassed holdout rules.** `get` is now an owner-display read only. It refuses final-holdout cases (`final_holdout`), which can be read only through `select`, and every `select` is logged. `delete` still works on them.
- **S3, one principal consenting for another.** A grant covers a feedback record only if `grant.principal_id == Feedback.principal_id`. Owner policy: error, outcome and case records have no principal owner yet, so shared selection denies them (`owner_unknown`) until persistence binds a tenant owner (T044). Personal adaptation is unchanged.
- **N2, prospective grants (orchestrator decision; the owner may overrule).** `ConsentGrant.covers_prior` defaults to False. A record made before the grant is shared only if it is True; otherwise it is excluded as `recorded_before_consent`.
- **N6.** `outcome_of` refuses a version outside 1..len(versions) (`version`).
- **N3, partial.** An outcome with an executed disposition must have a `proposal` subject (`subject`). Checking that the fact belongs to the same tenant and subject needs persisted facts: a persistence gap, not a pass.
- **Documented, no code:**
  - N1: `experiment_id` must come from the registered experiment (T044 binding); today the caller supplies it.
  - N4: an `evidence_digest` must digest an evidence id, never a numeric value. The type cannot enforce this.
  - N5: `affected_uses` flags a use when its first covering consent is revoked, even if another grant still covers it. That is over-conservative but safe.
- Mutation controls were not re-run after these fixes.
