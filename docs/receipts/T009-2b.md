## Changes
- `packages/adapters` (`qw-adapters`, import `qw_adapters`): the T008 section 2 module that owns the PostgreSQL implementations.
  - `migrations.py`: forward-only runner. Files `NNNN_lower_snake.sql`, contiguous from 0001. `public.schema_migrations(version, name, checksum sha256, applied_at timestamptz)`. Before applying anything it refuses: bad or non-lowercase names (`.SQL`), symlinks, duplicate versions, gaps, an applied file whose checksum or name changed, an applied version without a file, a pending file older than an applied one, and any top-level BEGIN/START TRANSACTION/COMMIT/END/ROLLBACK/ABORT/SAVEPOINT/RELEASE/PREPARE TRANSACTION/DISCARD/RESET ALL/SET or RESET ROLE/SESSION AUTHORIZATION statement. A conservative regex scanner skips comments (refusing nested `/*` comments), quoted strings (including `E''` backslash escapes), quoted identifiers and dollar-quoted bodies, and refuses a file with an unterminated quote or comment. `BEGIN ATOMIC` bodies are refused. A session advisory lock (key `0x71776D6967726174`, per database) serialises runners; a failing unlock is added as a note to the original error instead of replacing it. Each migration runs in its own transaction; versions after 0001 run under `SET LOCAL ROLE qw_migrate`. Inside the same transaction the runner checks that the transaction, the session user and the current role are unchanged, runs `RESET ROLE; RESET ALL` (so search_path and other settings do not leak), checks that every user object (schemas, relations, functions, types, operators, collations, conversions, operator classes/families, text search configs/dictionaries, extended statistics, event triggers, extensions, FDWs, foreign servers, publications, languages) outside `pg_*`/`information_schema` is owned by `qw_migrate` (except the schema_migrations ledger), runs the schema guard, and only then inserts the version row. Requires an autocommit connection and a UTF8 database. It reads no environment and opens no connection.
  - `schema_guard.py`: catalogue check (pg_attribute/pg_type/pg_range) over tables, partitioned tables, views, materialized views, foreign tables and composite types in every non-system schema. It resolves domains, arrays, ranges and multiranges. Rule 1: no `real`, `double precision`/`float` or `money`. Rule 2: **every** `numeric` column must be `numeric(p,s)` with (p, s) a section 3.2 storage class: (38,12), (24,12), (30,18) or (20,6), unless it has a reviewed entry in `EXEMPT` (empty). Rule 3 (second net): a money-named column must be numeric. Names are split on non-alphanumerics and camelCase and lowercased; any token in `MONEY_TOKENS` (now including px, value, pnl, rate, fx, equity, debit, credit, dividend, premium, margin, …) makes it money-named unless the last token is a non-amount suffix (`currency`, `id`, `source`, `type` …). The guard raises on a non-UTF8 database. The convention is documented in the module docstring. An event trigger was not used: it needs a superuser, later migrations run as non-superuser `qw_migrate`, and managed PostgreSQL may forbid it. There is therefore no `0002` migration; the guard is enforced by the runner on every migration and by the tests.
  - `sql/0001_roles_and_baseline.sql`: creates the section 5 roles exactly — `qw_migrate`, `qw_app`, `qw_worker`, `qw_ingest`, `qw_assessor`, `qw_release` — if missing and resets each to `NOLOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS INHERIT`. It revokes ALL on the database from PUBLIC and grants CONNECT to those six roles, revokes CREATE on `public` from PUBLIC, creates schema `app` owned by `qw_migrate` with USAGE only for the five runtime roles, and revokes default EXECUTE on `qw_migrate`'s functions and USAGE on its types from PUBLIC. The supported bootstrap path is a superuser session. The task brief also mentioned `qw_owner`; section 5 does not list it, so it is not created. Tests: `tests/conftest.py` (harness), `tests/test_migrations.py`, `tests/test_schema_guard.py`. DB tests are marked `db`.
- Harness: `QW_TEST_DATABASE_URL` (superuser URL) if set; otherwise initdb + pg_ctl from `QW_PG_BIN` (default `/usr/lib/postgresql/16/bin`) into a 0700 `mkdtemp` directory, with `listen_addresses=''` (unix socket in that directory only), `--auth-host=reject` and `fsync=off`. Stop and `rmtree` run in nested `finally` blocks. As root it runs the binaries as the `postgres` OS user through `runuser` (initdb refuses root); without `runuser` or that user it skips with the reason. The fixture checks the server is major 16, that the user is a superuser and, for the harness cluster, that it has no TCP listener. Each test gets a fresh `UTF8`/`C` database from `template0`, dropped `WITH (FORCE)`. If no server is available the tests skip with the reason; with `QW_REQUIRE_DB=1` they fail.
- `pyproject.toml`: registers the `db` marker. `tools/check_no_float.py`: `adapters: ("src",)` in MONEY_PATHS (adapters persist money). `tests/test_guards.py`: `ALLOWED_THIRD_PARTY["adapters"] = {"psycopg"}`; every other package still rejects psycopg.

The job sets `QW_TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:5432/postgres` and `QW_REQUIRE_DB=1`. A step ensures `libpq5` is installed and prints the libpq version psycopg loads.

## Dependency and licence (R022, ADR-013 / A-09)
- `psycopg==3.3.6` (released 2026-09-18) as a runtime dependency of `qw-adapters` only, via `uv add --package qw-adapters`. `uv.lock` adds psycopg 3.3.6, `tzdata` 2026.5 (Windows-only marker, Apache-2.0, not installed here) and the workspace member. Licence: `LGPL-3.0-only` (installed metadata `License-Expression`). **Conditional** under the ADR-013 policy: it is used unmodified, never vendored, and loaded as a library. Containers that ship it must include the licence text and corresponding-source information. Legal confirmation stays open under QUAL23 (review A-09). Why plain `psycopg` rather than `psycopg[binary]`: the pure-Python build loads the system `libpq.so.5` dynamically (PostgreSQL licence), which matches the "unmodified, dynamically linked" condition. The binary wheel would also bundle libpq, OpenSSL and other native libraries into the Python environment, widening the licence inventory and the patching surface. Cost: the host needs `libpq5` (present here: libpq 16.15, `psycopg.pq.__impl__ == "python"`; CI installs it if missing). The C build (`psycopg[c]`) can be considered later for speed.

## Negative/adverse cases
- Runner: checksum tampering, a renamed applied file, a deleted applied file, a gap (0001, 0003), a duplicate version, bad names including `0002_upper.SQL`, a symlinked file, out-of-order history (row 2 deleted while 3 is applied), a failing migration (`SELECT 1/0`: earlier versions stay, no row and no table for the failing one or later ones), a non-autocommit connection and a SQL_ASCII database are all refused. A found defect, now fixed: on SQL_ASCII psycopg returns `text` as bytes; both the runner and the guard now require UTF8.
- Scanner (17 rejected before execution): `COMMIT`, the reviewer's `RESET ROLE; CREATE TABLE …; SET LOCAL ROLE qw_migrate;`, `SET SESSION AUTHORIZATION DEFAULT`, `set local role`, `Set Session Role`, `RESET ALL`, `begin`, `End`, `SAVEPOINT`, `ROLLBACK TO`, `abort`, `START TRANSACTION`, `RELEASE SAVEPOINT`, a commit after a comment, `PREPARE TRANSACTION` after a line comment, `DISCARD ALL`, and `BEGIN ATOMIC`. Accepted (9): those words inside strings, `E'it\'s; commit'`, quoted identifiers, `''` escapes, `$$` and `$b$` bodies, a quoted plpgsql body, `SET search_path`, and comments. Refused as unscannable (6): unterminated `'`, `"`, `/*`, `$$` and `E'\'`, and a nested `/* /* */ */` comment (the regex scanner refuses nesting).
- Dynamic escapes the scanner cannot see (DO + EXECUTE): `RESET ROLE` → create table → `SET LOCAL ROLE qw_migrate`; `SET SESSION AUTHORIZATION DEFAULT` → create table → `SET LOCAL ROLE`; and `RESET ROLE` → `CREATE SCHEMA rogue` are rolled back by the ownership check, leaving no table, no schema and no version row. A bare dynamic `RESET ROLE` and `SET SESSION AUTHORIZATION qw_app` are rolled back by the end-state checks, and the session afterwards has `session_user = current_user`. A migration setting `search_path` and `statement_timeout` leaves both at their defaults afterwards. A 0001 that terminates its own backend raises `… rolled back` with the note "advisory unlock also failed". The transaction-id check is now defence in depth: the scanner rejects every known way to end the transaction from the file. Concurrency: the test holds the advisory lock, starts two runners, observes in `pg_locks` that both wait, releases, and gets `[1, 2]` and `[]`. 0002 has no `IF NOT EXISTS`, so a double apply would fail.
- Guard: SYNTHETIC columns `real`, `float`, `double precision[]`, a domain over float8, a float8 range type, `money`, a view column and a composite-type attribute are reported. Unconstrained `numeric` (any name), `numeric(10,2)`, money-named `bigint`/`integer`/`text`, and the reviewer's `"Price" bigint`, `pnl numeric(10,2)`, `fx_rate numeric(10,2)`, `rate numeric`, `equity text`, `total_value integer` are reported. Allowed: a `numeric(38,12)` domain, `numeric(38,12)` (including `unit_px`), `(24,12)`, `(30,18)`, `(20,6)`, non-money `integer`/`text`, and a column listed in `EXEMPT`. Name rule cases: `unit_px`, `total_value`, `Price`, `pnl`, `fx_rate`, `rate`, `equity`, `debit`, `credit`, `dividend` and `unitPx` are money-named; `price_currency`, `fx_rate_source` and `created_at` are not. Migrations adding `double precision`, `ADD COLUMN w real`, `price numeric`, `pnl numeric(10,2)`, `"Price" bigint` or `score numeric` are rolled back with no version row. `column_type_violations` raises on SQL_ASCII. The numeric typmod decoder is checked against hand-packed values.

## Close-out: round-2 follow-up (branch `t009-closeout`, base `be053d7`)
- `migrations.py`: inside each migration's transaction, the runner snapshots role and privilege state as the session user before `SET LOCAL ROLE` and after `RESET ROLE`. The snapshot covers `pg_roles` names and attributes, `pg_auth_members`, the database, `public`/`app` schema and ledger ACLs, `pg_default_acl`, large-object owners, and every PUBLIC grant. PUBLIC grants are read from the effective ACLs of the database, user schemas, relations, columns, functions, explicit types, default ACLs, large objects, languages, foreign servers and FDWs.
  - It rolls back on: any role or membership created, altered or dropped, or any change to the database/schema/ledger ACLs, outside 0001; any new grant to PUBLIC; a default ACL defined by a role other than `qw_migrate`, or a removed one (which restores the built-in PUBLIC defaults); any large object created or changed, metadata or content, including one owned by `qw_migrate`; any change to `schema_migrations` rows (the runner inserts its own row after the check); and any change to `pg_db_role_setting` (`ALTER DATABASE/ROLE … SET`).
  - The pre-scan now keeps every token of a statement. It also refuses `set_config('role' | 'session_authorization', …)` (including the `pg_catalog.` and `E''` forms), `SET [LOCAL] "role"`, `SET session_authorization` and `GRANT … TO PUBLIC` / `"public"` (including `ALTER DEFAULT PRIVILEGES … GRANT … TO PUBLIC`).
