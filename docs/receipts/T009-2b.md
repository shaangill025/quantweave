## Changes
- `packages/adapters` (`qw-adapters`, import `qw_adapters`): the T008 section 2 module that owns the PostgreSQL implementations.
  - `migrations.py`: forward-only runner. Files `NNNN_lower_snake.sql`, contiguous from 0001. `public.schema_migrations(version, name, checksum sha256, applied_at timestamptz)`. Before applying anything it refuses: bad file names, duplicate versions, gaps, an applied file whose checksum or name changed, an applied version without a file, and a pending file older than an applied one. A session advisory lock (key `0x71776D6967726174`, per database) serialises runners. Each migration runs in its own transaction; versions after 0001 run under `SET LOCAL ROLE qw_migrate`, so their objects are owned by the non-superuser schema owner. Inside the same transaction the runner rejects a file that ended the transaction or changed the role, runs the schema guard, and only then inserts the version row. Requires an autocommit connection and a UTF8 database. It reads no environment and opens no connection (the composition root supplies one).
  - `schema_guard.py`: catalogue check (pg_attribute/pg_type/pg_range) over tables, partitioned tables, views, materialized views, foreign tables and composite types in every non-system schema. It resolves domains, arrays, ranges and multiranges. Rule 1: no `real`, `double precision`/`float` or `money`. Rule 2: a money-named column (last `_` token in `MONEY_TOKENS`, or a `_usd` suffix) must be `numeric(p,s)` with (p, s) a section 3.2 storage class: (38,12), (24,12), (30,18) or (20,6). The convention is documented in the module docstring. An event trigger was not used: it needs a superuser, later migrations run as non-superuser `qw_migrate`, and managed PostgreSQL may forbid it. There is therefore no `0002` migration; the guard is enforced by the runner on every migration and by the tests.
  - `sql/0001_roles_and_baseline.sql`: creates the section 5 roles exactly — `qw_migrate`, `qw_app`, `qw_worker`, `qw_ingest`, `qw_assessor`, `qw_release` — if missing and resets each to `NOLOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS INHERIT`. It revokes ALL on the database from PUBLIC and grants CONNECT to those six roles, revokes CREATE on `public` from PUBLIC, creates schema `app` owned by `qw_migrate` with USAGE only for the five runtime roles, and revokes default EXECUTE on `qw_migrate`'s functions from PUBLIC. The task brief also mentioned `qw_owner`; section 5 does not list it, so it is not created.
  - Tests: `tests/conftest.py` (harness), `tests/test_migrations.py`, `tests/test_schema_guard.py`. DB tests are marked `db`.
- Harness: `QW_TEST_DATABASE_URL` (superuser URL) if set; otherwise initdb + pg_ctl from `QW_PG_BIN` (default `/usr/lib/postgresql/16/bin`) into a `mkdtemp` directory, on a free 127.0.0.1 port, with `fsync=off`, stopped and deleted at session end. As root it runs the binaries as the `postgres` OS user (initdb refuses root). The fixture checks the server is major 16 and that the user is a superuser. Each test gets a fresh `UTF8`/`C` database from `template0`, dropped `WITH (FORCE)`. If no server is available the tests skip with the reason; with `QW_REQUIRE_DB=1` they fail.
- `pyproject.toml`: registers the `db` marker. `tools/check_no_float.py`: `adapters: ("src",)` in MONEY_PATHS (adapters persist money). `tests/test_guards.py`: `ALLOWED_THIRD_PARTY["adapters"] = {"psycopg"}`; every other package still rejects psycopg.
- `.github/workflows/ci.yml` (python job): `services.postgres` with `image: postgres:16`, `POSTGRES_HOST_AUTH_METHOD: trust`, port 5432 and a `pg_isready` health check. The job sets `QW_TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:5432/postgres` and `QW_REQUIRE_DB=1`. A step ensures `libpq5` is installed and prints the libpq version psycopg loads.

## Dependency and licence (R022, ADR-013 / A-09)
- `psycopg==3.3.6` (released 2026-09-18) as a runtime dependency of `qw-adapters` only, via `uv add --package qw-adapters`. `uv.lock` adds psycopg 3.3.6, `tzdata` 2026.5 (Windows-only marker, Apache-2.0, not installed here) and the workspace member.
- Licence: `LGPL-3.0-only` (installed metadata `License-Expression`). **Conditional** under the ADR-013 policy: it is used unmodified, never vendored, and loaded as a library. Containers that ship it must include the licence text and corresponding-source information. Legal confirmation stays open under QUAL23 (review A-09).
- Why plain `psycopg` rather than `psycopg[binary]`: the pure-Python build loads the system `libpq.so.5` dynamically (PostgreSQL licence), which matches the "unmodified, dynamically linked" condition. The binary wheel would also bundle libpq, OpenSSL and other native libraries into the Python environment, widening the licence inventory and the patching surface. Cost: the host needs `libpq5` (present here: libpq 16.15, `psycopg.pq.__impl__ == "python"`; CI installs it if missing). The C build (`psycopg[c]`) can be considered later for speed.

## Negative/adverse cases
- Runner: checksum tampering, a renamed applied file, a deleted applied file, a gap (0001, 0003), a duplicate version, bad file names, out-of-order history (row 2 deleted while 3 is applied), a failing migration (`SELECT 1/0`: earlier versions stay, no row and no table for the failing one or later ones), a file containing `COMMIT` or `RESET ROLE`, a non-autocommit connection, and a SQL_ASCII database are all refused. A found defect, now fixed: on a SQL_ASCII database psycopg returns `text` as bytes, which broke the name comparison. The runner now requires UTF8.
- Concurrency: the test holds the advisory lock, starts two runners, observes in `pg_locks` that both wait, releases, and gets `[1, 2]` and `[]`. 0002 has no `IF NOT EXISTS`, so a double apply would fail.
- Guard: SYNTHETIC columns `real`, `float`, `double precision[]`, a domain over float8, a float8 range type, `money`, a view column and a composite-type attribute are reported. Money-named `numeric` (unconstrained), `numeric(10,2)`, `bigint` and `text` are reported. Allowed: a `numeric(38,12)` domain, `numeric(38,12)`, `numeric(24,12)`, `numeric(20,6)`, and an unconstrained numeric with a non-money name. Migrations adding `double precision`, `ALTER TABLE … ADD COLUMN w real` or `price numeric` are rolled back with no version row. The numeric typmod decoder is checked against hand-packed values.
- Mutation checks (each reverted; all 12 killed): advisory lock removed, checksum check removed, guard call removed, `SET ROLE` removed, out-of-order check removed, transaction-escape check removed, domain resolution removed, array resolution removed, any numeric accepted for money names, database REVOKE removed, role attribute reset inverted, default-privilege revoke removed. Each failed 1–3 tests.
- Process: the tests were written alongside the implementation; no red run was recorded before the code existed.
