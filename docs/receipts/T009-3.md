- `apps/web/src/wire.ts`:
  - `DecimalString` brand. `parseDecimalString` and `isDecimalString` use the §3.2 grammar at the widest class bounds (26 integer digits, scale 18). They reject `-0`, exponents, `+`, leading zeros, bare `.`, whitespace, a trailing newline, non-ASCII digits and non-strings. Error messages echo at most 64 characters.
  - `formatDecimal` uses string and BigInt operations only. It groups digits with configurable group and decimal separators. With `fractionDigits` it rounds half-even (display rounding per §3.2) or zero-pads. A value that rounds to zero is shown without a minus sign (`-0.004` at 2 gives `0.00`). It re-validates its input even when the brand was forged by a cast.
  - The `Problem`, `FieldError` and `Reason` types follow C-01: `type`, `title`, `status`, `code`, `detail`, `correlation_id`, `retryable`, `retry_after_s`, `field_errors`, `reasons`, `error_schema: "1"`. `isProblem` checks a body at runtime. Unknown extra fields are ignored. The types are hand-written until the A-04 generator exists, and the field list should be re-checked when T010 publishes contract 0.2.0.
- Tests:
  - `src/wire.test.ts` has hand-computed expectations. It covers 2^53+1, 26-digit values and negatives, half-even ties in both directions, carry across a grouping boundary (`999.995` gives `1,000.00`), negative zero after rounding, separators, invalid `fractionDigits`, envelope negatives, and the money-guard lint rule against SYNTHETIC samples.
  - `src/main.test.tsx` is an a11y structure smoke test. It is not a conformance assessment.
- Money guard: `no-restricted-syntax` in `eslint.config.js` (`moneyGuard`) bans any reference to `Number`, `parseFloat` or `parseInt` in all of `src`. That covers calls, `new`, aliases, `.map(Number)`, `(0, Number)(x)`, `Reflect.apply` and destructuring from `globalThis`. Only `Number.isInteger`/`isSafeInteger`, non-computed property names and object-literal or type keys are exempt. The rule also bans those names read from `globalThis`, `window`, `self` or `global` (dot or string-literal index), and unary `+`. This is stricter than "money fields only". Known gaps, noted in the config: `x * 1`, `x - 0`, `Math.*` on strings, computed names such as `globalThis["Num" + "ber"]`, and JSON numbers.
- `tools/check_web_licenses.mjs`: inventories every package in `pnpm-lock.yaml`. Licences come from `pnpm licenses list --json` (and `--prod`) for installed packages, and from a registry-recorded `OFF_PLATFORM` table for optional binaries of other platforms. A lockfile package that is neither installed nor recorded fails, and so does an installed package that is missing from the lockfile. `main()` runs only when the file is executed, not on import.
  - It fails on a denied licence (GPL/AGPL, SSPL, BUSL, Elastic, Commons Clause, non-commercial, UNLICENSED), an unknown or empty licence, an unparsed compound expression, or a licence outside the ADR-013 allow list that has no package-scoped review keyed by `name@version`. Production dependencies must have an allow-list licence, and reviews do not apply to them.
  - It prints the direct-dependency inventory.
  - `--self-test` runs 20 negative and positive controls.

The package-manager cache is disabled. Steps: `pnpm install --frozen-lockfile --ignore-scripts`, typecheck, lint, test, build, then the licence self-test and gate.
